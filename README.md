# CrediLens 1.1.5

校园反诈识别助手，面向学生收到可疑兼职、缴费、账号和退款消息时的初步核验。主流程为提交内容、检查原文证据、执行处置清单、完成判断练习。

1.1 将固定模板原型升级为可运行的本地分析应用，并提供可配置的模型后端。无需安装生产依赖；保留原生 HTML、CSS、JavaScript，便于三人团队逐步理解和维护。模型密钥只在本机 `.env` 配置，不写入源码或升级包；启动时默认选择本地模式。

1.1.1 修正正常内容统一显示“信息不足”的问题：为有明确否定语境的完整反诈提醒、无敏感操作要求的图书馆到期通知增加原文内容线索、具体解释与匹配建议。云端的 unknown 不再仅因身份未核实而覆盖已有的内容语境判断；实际危险要求仍优先，模型也不能凭一句“安全”降低本地风险。输入区、侧栏与页脚同步显示本地或云端处理状态。

1.1.2 将分析对象、风险发现、信息充分性、来源核实分开呈现。新增“不适用风险评级”，用于没有具体风险事件的日常交流、分析结果描述等；信息不足时只追问相关背景，不虚构交易或对方账号。正常内容不再显示固定数字分数。技术处理失败独立标记，不解释成内容安全或语义信息不足。云端可用带原文引句的 `content_assessment` 补充本地未覆盖的内容用途判断，仍不能消除已有风险或为链接、敏感入口背书。

1.1.3 将截图转录与风险分析拆成两步。授权后识别文字，用户可查看大图、修改文字并明确确认，再提交文字分析。识别阶段不产生风险评级或分析记录；修改文字会取消确认，更换截图会清空文字、确认与图片授权。后端拒绝直接把图片提交到风险分析接口，分析阶段不重复上传图片。确认状态只表示用户声明，不能证明转录准确或来源真实。

1.1.4 为文字、链接、截图统一增加选填“补充背景与核验目标”（最多 1,000 字符）。背景单独脱敏、发送、展示与导出，不混入原文或本地风险评分。保留原文后追加“是真的吗”的输入，不猜测拆分用户原话；常见核验提问或填写背景时提供有边界的核验回应。只填背景时要求补充原文，不把用户自述当作消息证据。同步修复截图分析状态，并用受控风险摘要替代模型可能过度认定诈骗的摘要。

1.1.4 同时包含启动选择弹窗：每次打开或刷新页面时弹出分析方式选择框。默认勾选本地；云端服务配置检查成功后才可选云端，选择后点击进入才应用，不自动发送分析内容。关闭或按 Esc 以本地模式进入，不保存上次的云端选择。服务检查失败或超时、本地文件直开时仍可使用本地模式，进入后也可从设置切换。弹窗后续的焦点样式与动效小修并入 1.1.4。

1.1.5 为链接分析功能升级：不建立学校域名白名单，不要求网站预先收录。报告分开显示六项结构检查、消息用途与风险、公开出处检索、页面未检查状态。仅有链接也给出实际检查结果，而不只显示“信息不足”。云端可用原文引句补充用途判断，但模型记忆不能充当机构归属证据。新增可选 Tavily 域名出处检索，使用独立密钥与单次授权；检索线索不是官网认证，不能消除原文风险。此前将这批新功能标为 1.1.4 不准确，本次统一更正为 1.1.5。

版本管理：样式、文案和局部缺陷修复通常并入当前版本；新增功能、外部服务或配置项、完整业务流程变化应单独发布新版本。本次有独立检索服务、配置及授权流程，属于功能升级，不按微小更新合并。

1.1.5 引用修正：安全知识及报告中的固定知识外链仅使用已核对的中国官方具体文章，不再使用国外来源或公安部首页代替文章。当前 6 条知识关联 3 篇广州市公安局文章，另 4 条为无外链的项目规则说明。展示真实文章标题、发布单位、发布日期、链接核对日期及支持范围；项目整理内容不冒充官方原文。此项引用修正并入 1.1.5，不另升版。

1.1.5 报告质量修正：合并同一付款行为的重复证据，保留关键上下文，约束模型解释不越过原文证据；区分明确的日常交流，并避免将“没有转账”等否定描述误判为付款要求。保持当前版本号。

1.1.5 链接输入小修：支持短信中不带 `http(s)://` 的域名和路径；报告标为“未注明”协议，不推断 HTTPS 或传输加密。Tavily 授权开关仅在单独配置 `TAVILY_API_KEY` 且选择云端模式后启用，未配置时说明原因。保持当前版本号。

## 运行

本地模式：直接打开本目录的 `index.html`，无需网络。文字分析、URL 结构检查、截图文字分析、案例与知识搜索、会话记录、报告导出均可用。

推荐启动项目服务（Node.js 22.13 或更新版本）：

```powershell
cd 'D:\传智杯\CrediLens1.1.5'
node server.js
```

打开终端显示的地址，默认 http://127.0.0.1:5173。端口占用时自动尝试后续 10 个端口。也可指定 `node server.js 5174`。服务只监听本机；关闭启动它的终端可停止前台服务。

## 配置云端模型

后端适配支持 `/chat/completions`、JSON 输出及标准 `messages` 格式的模型服务。先从 `.env.example` 新建本机 `.env`，填写：

```dotenv
LLM_BASE_URL=https://your-provider.example/v1
LLM_API_KEY=your-server-side-key
LLM_MODEL=your-model-id
LLM_VISION=false
PORT=5173
```

`LLM_BASE_URL` 为 API 基址，不包含 `/chat/completions`；仅本机模型允许 HTTP。需视觉模型时将 `LLM_VISION` 改为 `true`，并确认提供商支持 `image_url`。模型必须支持 `response_format: {"type":"json_object"}`。不支持这些字段的服务会返回本地降级报告，需要在 `model.js` 做提供商适配。

重启 `node server.js`，打开页面后在弹窗选择云端分析并点击“进入工作台”；也可先使用本地，再从右上角设置切换。每次打开或刷新重新选择，默认本地，不自动沿用上次的云端授权。弹窗只查询本机 `/api/status` 检查配置，不调用付费模型，也不发送输入内容；“已配置”不代表已验证密钥、额度或模型可用性，实际请求仍可能失败并回退。密钥不会传到浏览器，`.env` 已加入忽略清单且不在静态文件白名单中。

文字在前端和服务端分别执行一次脱敏。云端文字分析会把脱敏原文、单独标注的补充背景和 Top 3 知识摘要发送到配置的提供商；填写背景不会增加独立请求，但可能增加输入 token。截图转录是独立请求，仅发送单独授权的图片，不发送补充背景。每个请求限时 25 秒，前端限时 40 秒。文字分析失败、格式无效、引用无法匹配原文时，返回明确标注的本地回退结果。识图失败则提示重试或手动填写，不生成风险报告。云端截图完整流程通常包含一次识图调用和一次文字分析调用，各自可能收费；重复识别或重新分析也可能收费。

### 可选：联网查找域名公开出处

模型 API 不自动具有浏览或搜索能力。本轮提供独立的 Tavily Search 适配器；这是检索服务的实现选择，不是更换模型。无需安装依赖，也不要求立即开通，不影响已有功能。服务端 `.env` 可追加：

```dotenv
TAVILY_API_KEY=your-separate-tavily-key
```

不要在这里复用模型密钥，也不要把真实密钥放入网页或更新包。重启服务，切换云端模式，填写链接，在链接区勾选本次检索授权，再点击分析。未配置时开关不可选；配置状态不代表已验证密钥或额度。当前 UI 将所有联网操作限制在云端模式；因此还需已有模型配置才可在界面启用检索。

- 仅向固定 HTTPS 服务 `https://api.tavily.com/search` 发送实际主机名及固定查询词，不发送路径、参数、片段、消息或背景；模型分析仍按原有云端授权发送脱敏链接与文字，两条发送边界不同。
- 检索与模型分析并行；检索限时 8 秒、最多展示 5 个去重的相关出处，标记服务、查询域名及时间。新建、换链接、切换模式、提交后均清除检索勾选；再次检索须重新授权。恢复历史只展示旧结果，不重新联网。
- 拒绝 IP、本机和保留名称的检索；不直接访问用户链接、不跟随跳转。对来源 URL 限制协议、凭据、端口及主机，移除跟踪参数与片段；摘要以纯文本展示。检索来源可能不可靠或过时，用户点击来源仍应自行谨慎核对。
- 检索摘要不会送给模型执行，也不进入原文证据或风险分。域名被某页面提及不证明机构归属，AI 记忆也不作为认证；当前不自动输出“已确认官网”。没有结果、服务失败、超时均不算网站恶意证据。
- 模型或检索各自失败时，另一个结果仍可保留；整个前端请求失败时明确标记没有收到检索结论。检索可能收费，实际费用及数据处理政策以提供商为准。本次开发只使用模拟检索与模拟模型，不验证真实账户可用性。

后续若要读取目标网页，需要单独实现 SSRF 防护、DNS/跳转逐次校验、下载与正文大小限制、隐私授权及提示注入隔离，不应直接把 `fetch(用户URL)` 接入现有服务。

### 工作流与接口

```text
截图 → 单独图片授权 → 云端转录（不作风险判断）→ 对照图片编辑并确认文字
                                                               ↓
文字 / 链接 → 输入校验 → 常见字段脱敏 → 本地信号 / URL 解析 → 关键词知识检索
                                                   ↓
                                  本地报告 或 服务端模型分析
                                                   ↓
                                 JSON 校验 → 原文证据校验
                                                   ↓
                                风险报告 / 明确标记的本地回退
```

- `GET /api/status`：版本、模型是否配置、模型名称、视觉能力、`searchConfigured` 及检索提供商，不返回任何密钥。
- `POST /api/transcribe`：接收 `{mode:'image', text:'', image, imageConsent:true}`，返回 `{status:'needs_review', text, redacted}`；不返回风险评级。无法识别、超时、返回截断或配置缺失时返回非成功状态和通用错误信息。
- `POST /api/analyze`：接收 `{mode, text, url?, background?, searchConsent?}`；`searchConsent` 必须为布尔值，只有链接模式可设 `true`，省略或 `false` 不检索。客户端不能提交自己的归属认证结果。`background` 必须是最多 1,000 字符的字符串，旧请求可省略。截图模式要求非空文字及 `imageTextConfirmed:true`，不接受图片。确认后可使用没有视觉能力的模型进行文字分析。仅文字模式可在原文为空时用非空背景请求补充材料反馈，不生成虚构证据。
- 报告增加 `background`（脱敏用户自述）和 `verificationResponse:{answer,backgroundAdvice}`（无需回应时为 null）。本地与云端共用受控回应，说明风险判断和真假核实的区别，不提供任意聊天答案。背景中的风险描述不会单独改变本地评级，模型证据也只能引用原文或链接；不将背景并入证据检索。
- “我已经付款”等少量明确第一人称付款表述可触发标注为用户自述的处置建议，不改变风险评级。否定、假设和疑问不应被当作已付款。该识别是有限规则，不代表完整语义理解；复杂描述仍可能未覆盖。
- 截图确认报告增加 `inputReview:{status:'user_confirmed',scope:'text_only'}`，导出包含该声明与文字分析边界，不保存图片、旧识别草稿或修改前文字。它不是服务器验证过的图片准确性或来源证明。
- 报告主要字段：`id`、`createdAt`、`level`、`score`、`contentType`、`contentLabel`、`assessment`、`processing`、`missingInformation`、`evidence`、`actions`、`uncertainty`、`references`、`original`、`source`、`checkedActions`。`quiz` 在不适用或没有练习依据时为 `null`。
- `level` 新增 `not_applicable`。`assessment` 独立记录 `applicability`、`riskSignals`、`information`、`sourceVerification`；来源状态固定为 `not_verified`，不会接受模型自称已核实。`processing.status` 为 `completed`、`fallback` 或 `failed`；技术失败时风险为 `not_assessed`、信息为 `not_evaluated`，不生成内容风险结论。
- 新模型协议可返回 `content_assessment: {type, quote}`；用途包括提醒、日常通知、结果描述、日常交流与未知。引句必须来自原文或图片转录，不能用虚构片段、局部问候或无依据的“安全”替代事件分析。旧协议没有此字段时仍可使用本地判断。
- 模型证据的 `quote` 必须逐字存在于提交的脱敏文字中。截图转录草稿须由用户确认后才能成为分析输入。模型不能消除本地已发现的风险；没有可验证线索时不能把未知内容升级为低风险。
- 服务限制 JSON 输入、请求体大小、每分钟 20 次分析、最多 3 个并发分析，拒绝跨来源调用。当前为本机应用，公网部署前需独立补充认证、配额与部署配置。

```text
  styles.css             桌面与移动端样式

```

新手 A 可负责页面、响应式、键盘和错误交互；新手 B 可维护案例、知识来源、评测和讲稿；负责人负责 `engine.js`、模型接入、接口和集成。每次修改案例或规则后运行回归检查。

评测脚本从 `tests/evaluation.json` 读取 56 条人工定义的回归样本，生成 `test-results/evaluation.json`，包含标签与可选维度检查、混淆矩阵和逐条结果。该集合是工程回归集，未做独立验证，不能把结果写成真实场景准确率。由于新增不适用状态，旧 E30（hello world）从信息不足改为不适用，属于产品标签定义调整，不能视作模型准确率提升，版本间一致率也不可直接比较。1.1.4 新增 E49–E56，覆盖附带提问、背景分离和链接背景。

## 判断与数据边界

- 本地风险分按信号权重相加，上限 98；50 及以上为高风险，20 至 49 为中风险。较弱信号缺乏背景时为待核验。低风险、待核验和不适用均使用 `score: null`；高、中风险保留旧启发式分数。低风险需要有原文支撑的明确语境，且没有命中的风险要求，不能仅凭自称官方或 HTTPS 下结论。
- 报告会合并同一项付款操作中的重复线索，并优先保留包含操作主体和条件的原文片段；模型不得把反诈提醒本身当成危险操作，也不能将“需要核验”扩写成已认定诈骗或已核实身份。明确的见面、课程和图书馆安排可归为日常交流；“没有/尚未转账”等否定表述不会单独被当作付款要求。信息充分性与来源核实仍分别记录。
- 这些权重尚未经过统计校准，分数不是诈骗概率，也不能作为公安、学校或平台的认定依据。
- 规则仅覆盖有限的中文表达及少量英文指令。否定、引用、转述、谐音和复杂上下文仍可能误判。
- 追加“是真的吗”的回归测试覆盖若干常见组合，不是任意问题理解能力。系统不自动判断哪一句属于用户、哪一句属于转述，不擅自删除原文；填写独立背景可减少歧义。模型引句校验只能证明片段出现过，不能证明风险解释或分类正确，模型证据解释仍需人工复核。
- 知识条目采用关键词检索，不是向量检索。云端生成利用检索摘要作为上下文；当前未实现向量库、混合检索或独立检索评测。
- 知识内容为项目整理摘要，页面明确区分原文证据与参考知识。部分来源为官方宣传入口，需继续补充精确条目和更新时间。
- 图片识别转录无法仅凭字符串校验证实，需要用户对照原图复核。常见字段遮盖也不能保证覆盖全部个人信息。
- 不进行网页抓取、域名信誉查询、主动扫描、真实身份验证或自动报案。不将用户输入与图片写入服务端文件或持久化数据库。
